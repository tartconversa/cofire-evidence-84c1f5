# 产品说明：掺烧试验的证据放行与运行边界

`cofire` 是掺竹燃料替代试验的分析应用。它接收按班次记录的投料、煤种、
负荷、排放、蒸汽交付与事先登记的试验安排，在试验结束后给出能约束下一
轮试验的结论，而不是只给处理前后的均值对比。全部输入为本地合成资料，
应用不连接、更不控制任何真实装置。

## 数据流

```
资料包(data/*.csv + catalog.json)
  │  sourcepack 完整性核对（字段、类型、键、引用、摘要）
  ▼
班次视图（cofire.model）      ← 测点只聚合成班次，不进入计数
  ▼
登记（cofire.registry）       ← reviews 表即事先登记；首次查看后冻结
  ▼
逐轮查看（cofire.analysis）   ← 只在登记查看日按序贯界值解释显著性
  ▼
下一轮判断（cofire.recommend）← 效果、风险、证据范围、停试合成判断
  ▼
运行交接（cofire.handoff）    ← 可用范围、不确定性、未执行计划、结论限制
```

工作区（`cofire init` 建立）持久化登记、班次、查看、判断与审计轨迹；
每条判断都记录数据截止点与登记哈希（判断口径），可用 `why` 回查。

## 判断口径

口径随登记哈希版本化，任何一轮判断都能回查到当时生效的口径。

### 三种估计口径

- **原定方案（ITT）**：按计划替代比分组。安全停试、调度改负荷的班次
  保留在内，不悄悄删除。
- **实际可运行（PP）**：无偏离记录、执行替代比与计划之差 ≤0.02、实际
  负荷与计划之差 ≤0.05 且在登记负荷范围内的班次。
- **无法识别部分**：安全停试班次的后续反事实、已登记但未产生测点的
  班次。单列说明；ITT 保留停试班次观测值所依赖的假设（停试班次结局
  可代表）无法从资料验证，结论限制中明示。

效果估计为班次级 `coal_per_steam` 的线性调整差值（处理哑变量 + 实际
负荷 + 含水率 + 煤种 + 炉组 + 前序班次计划替代比，滞后阶数取各炉组
`carry_window_shifts`）。

### 显著性与查看纪律

- 主要指标 `coal_per_steam`，登记目标为差值上界（负值表示期望降低）。
- 单侧 alpha=0.025，O'Brien-Fleming 形消耗；信息比例 = 可见班次数 /
  登记末次查看应见班次数。查看日 8/16/24 对应信息比例 1/3、2/3、1。
- 下列行为使确认性解释失效（结果仍可用，但只标注为探索性）：
  冻结后修订登记字段、在未登记日查看、重复查看、只取部分炉组查看。
- 效果结论只能来自已执行的登记查看；风险监测使用全部可见资料，不占
  显著性额度，但也无权给出"效果确认"。

### 风险与证据范围

- 越限与蒸汽不足按**班次有无**评估，不按测点数稀释；区间为 Wilson。
- 放行按登记上限的**绝对口径**：区间上界 ≤ 上限为"上限内"，下界 >
  上限为"超上限"，其余"未决"。
- 证据范围按工况格（替代比 × 负荷带 0.1 × 煤种 × 含水率带 5%）计数：
  比例层 ≥8 班且工况格 ≥2 班才算有支持。没有支持的工况不得用全厂或
  对照的平均安全外推。
- 继续试验的门槛与放行不同：不劣于对照（Newcombe 差值区间下界 ≤0）
  且无未复核停试，可在监测下继续积累证据，但不得放行。

### 下一轮请求的判断

| 判断 | 含义 | 触发 |
| --- | --- | --- |
| accept | 可放行 | 支持齐全、效果达标、两类风险上限内、无未复核停试 |
| continue | 可继续试验（不可放行） | 效果或风险证据未齐，但不劣于对照 |
| hold | 暂停复核 | 比例或工况格内有安全停试，或证据缺口需先补 |
| reject_unsupported | 拒绝（无支持证据） | 比例从未试验，不能外推 |
| reject_risk | 拒绝（不满足风险上限） | 越限率或不足率确认超上限 |
| reject_effect | 拒绝（效果确认不达标） | 调整差值区间下界仍高于登记目标 |

执行状态处置：**approved（已批准未开始）**每轮重评，依据不再成立即
建议撤销；**running（正在执行）**保留原批准依据，仅在判断转坏时发出
复核提示；**draft** 只给参考意见。试验未完成（班次数不足）只能判
"证据不足"，不能判"燃料无效"。

## 使用

```bash
python3 -m cofire check  <资料包>                 # 完整性核对
python3 -m cofire init   <工作区> --pack <资料包>  # 建区并并入首轮
python3 -m cofire look   <工作区> --day 8          # 执行登记查看
python3 -m cofire decide <工作区>                  # 下一轮判断
python3 -m cofire ingest <工作区> --pack <资料包>  # 并入新一轮
python3 -m cofire why    <工作区> N1               # 回查建议为何变化
python3 -m cofire handoff <工作区> -o handoff.md   # 运行交接报告
python3 -m cofire status <工作区>                  # 概览
python3 -m cofire amend  <工作区> --set 字段=值    # 修订登记（冻结后失效）
python3 -m cofire synth-round2 <目录>              # 生成合成第二轮（演示）
```

典型流程：建区 → 按 look_days 逐次查看 → decide 得到首轮判断 → 运行方
录入新一轮资料（ingest）→ 再 decide → 用 why 查看每条建议为何变化 →
handoff 向运行方交接。

## 测试

`python3 -m unittest discover -s tests -v`，行为核对点：

- `test_model.py`：班次是分析单位；测点复制后统计与计数不变；前序
  滞后按炉组窗口接好。
- `test_registry.py`：首次查看即冻结；冻结后修订、未登记查看、部分
  炉组查看都使确认性失效；登记哈希随口径变化。
- `test_analysis.py`：查看只见到 `available_at` 不晚于截止的班次；
  OBF 界值早严后宽；ITT 保留停试、PP 剔除、不可识别部分单列；风险
  按班次而非测点计数。
- `test_recommend.py`：未试比例拒绝外推；不足率上限低于基线时拒绝
  放行并说明属基线冲突；停试比例暂停复核；执行中请求保留依据并提示
  复核；试验未完成不得判无效；证据齐全才放行；建议变化可解释。
- `test_flow.py`：命令行端到端两轮流程，含合成第二轮、复核变化与
  审计轨迹。
- `test_handoff.py`：交接报告各节齐全，限制与外推禁令明示。
